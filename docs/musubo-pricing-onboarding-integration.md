# musubo 新料金・利用開始フローの実装接続図

設計の正本は `musubo-pricing-v12-uiux-20261106.pen`。この文書は、設計済み画面を既存の課金実装に接続する際の境界を記録する。画面部品やメールの存在だけで、新料金を公開済みと判断しない。

## 確定した料金とタイミング

- 利用条件は運営が申込を承認する時点で、会社名と適用期限をサーバーで照合し、承認時の単価・無料期間をスナップショットとして固定する。特別割引はLINE基本料金だけに適用し、統括機能・友だち超過・追加連携枠には重ねない。
- 通常の無料期間は30日。条件ごとに日数または月数を設定でき、3か月などを扱う。起算日は最初のLINE有効化日。カード登録やログイン作成では起算しない。
- LINE基本料金は1個目¥5,900、2〜5個目は各¥7,900、6〜10個目は各¥6,900（税込・月額の初期値）。年払い10%割引はこの基本料金だけ。統括機能は2個以上で月額¥5,500、追加連携枠は1枠月額¥3,300、友だち超過は基準から1万人ごとに月額¥1,100（いずれも初期値）。オプションは年払い中も月次請求する。
- 各LINEでGoogleマイビジネスとInstagramをそれぞれ1個まで基本料金内で連携できる。追加枠は両サービスのうち多い方の連携数から1を引く。実店舗数を請求基準にしない。11個以上は個別見積もりへ進める。
- 有料利用中の追加は支払いが成功するまで新しいLINE・連携先だけを保留し、既存の利用は継続する。保留期限は7日。連携解除は即時、追加枠の減額は次の月次請求日から。支払済み期間を返金しない。
- 最後のLINEを0個にする場合、無料期間中は請求を始めず終了する。月払いは次の請求日、年払いは次の更新日での終了を初期選択にし、即時終了は別に選べる。会社アカウントと請求履歴を残す。再開時に新しい無料期間を与えない。
- 個別見積もりは最終単価と期限を保存し、期限内の同意を確定させる。同意済みなら見積もり期限後もカード登録を続けられる。未同意で期限切れなら再発行と再同意が必要。
- LINEが11個以上の個別見積もりは、同意したLINE契約枠の基本料金を無料期間終了後の初回請求から適用する。接続済みが契約枠より少なくても基本料金は減らず、契約枠内の後続接続で基本料金を重ねて請求しない。追加連携枠と友だち超過などのオプションは実際の利用に応じて別計算する。契約枠を超える追加・枠数の減少は見積もりの改定と同意を要する。この条件を見積書・同意画面へ明記する。
- 接続後のLINE統計は、LINE公式APIの `followers` から `blocks` を引き、両値が確定した前日分だけ採用する。未確定・欠損時は人数を推測して確定請求しない。[LINE公式の指標定義](https://developers.line.biz/en/reference/messaging-api/nojs)を確認済みで、`followers` は退会後も減らない累積値である。この差分を厳密な現在人数として請求する前に、顧客表示・異議申立て時の扱いを確定する。

## 公開前に必要な接続

1. **DBと承認**：migration 756の作成、利用条件の版と承認時スナップショット、通常料金と見積もりの同意、追加操作の保留、最初のLINE有効化日、各サービスの連携数の保存先まで実装した。DB適用前に番号と差分を再確認する。承認した条件から新契約行を起こす処理は接続済み。
2. **運営API**：利用条件の版更新、会社限定と期限の照合、申込承認、見積もり作成・送信前確認・送信を実装し、画面に接続した。送信結果が不明なときの運営回復、コード発行は未完了。送信はプレビューの一致を要求する。
3. **顧客API**：通常料金のサーバー計算・同意保存、見積もり閲覧・期限内同意、カード登録の同意ゲートを実装した。LINE追加と最後のLINEの終了予約・即時終了・予約取消を接続した。終了意図をDBへ先に保存し、Stripeの基本契約と月次オプションを照合して停止する。未完了の外部操作は定期ジョブで再確認する。追加連携枠の操作と利用再開は未接続。画面の見積もり額や日付をそのまま請求根拠にしない。
4. **Stripe契約**：既存のStripe契約は旧 `light/standard/pro` とAPI `2024-06-20` を前提としている。年払いのLINE基本料金と月次オプションは別契約にし、LINE初回有効化後の作成、結果不明後の照合、署名済みWebhookの請求成功・失敗を接続した。検証用Stripeには専用商品二つを作成し、IDを検証Workerの設定ファイルへ記載した（未配備）。LINE追加分は独立した請求書で決済し、成功前は新規LINEだけを保留する。日次のLINE統計と次回請求日を使う定期料金の再照合もコード化した。検証環境での無料期間・実請求・日割り・通知順序の再現が残る。Stripe pending updateは通常約23時間で期限切れになるため、設計済みの7日間の追加保留はmusubo側の状態として保持して再試行する。追加分の失敗を通常の更新請求失敗と識別し、既存利用へ `past_due` を伝播させない。
5. **有効化ゲート**：最初のLINE接続が完了したときだけ無料期間を開始する。2個目以降は料金の確認と本人確認を済ませてから接続ウィザードへ進み、決済成功後に追加LINEを有効化する。支払い失敗中も既存LINEは利用可能。Stripe請求書の重複・期限切れを照合する処理と定期回復を追加した。接続直後に保存が失敗する境界と検証Stripeの実際の請求結果は公開前に再確認する。
6. **画面の入口**：運営の利用条件編集・申込承認条件選択・個別見積もり編集とメール送信前確認、顧客の通常料金確認・見積もり同意・カード登録の入口を接続した。静的公開に合わせ、個別見積もりのURLは `/hq/onboarding/quotes?id=...` とした。再ログイン時も保存済みの利用開始手順へ戻す。旧ウィザードの友だち数質問 `Q3. 友だちの数は50万人を超えていますか？` は削除し、後続の質問番号も詰めた。初回LINEの接続直前にLINE統計の累計が50万人を超える場合は個別相談へ止める。統計が取得できない場合は接続を止めて再試行を案内する。LINE追加と最後のLINEの終了画面はサーバー状態へ接続した。連携解除・再開画面は未接続。
7. **メール・通知**：Mail 01〜25の発火条件、再送の冪等性、受信者、送信失敗後の回復を接続する。送信処理を本番で有効にする段階では通常の外部通信承認ゲートを守る。
8. **検証と配備**：機能別の試験、型検査、ビルド、PenとのPC・スマートフォン照合、共有検証環境の順番待ちと完全SHA確認を行う。Codexの担当範囲はコミットまで。push・PR・統合・配備はリポジトリの司令塔運用に従う。
