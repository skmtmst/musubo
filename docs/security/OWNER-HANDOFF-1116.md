# 本番前にオーナーがやること（D6・1枚）

本番公開（11/25）の前に、オーナー（ケンタさん）とマサトさんが2人でやることを上から順に並べた1枚です。秘密の値（鍵・トークン・パスワード）は書かない・見せ合わない・貼らないが決まりです。「値は自分で入れる」とだけ覚えてください。終わった行には日付・名前・確かめた証拠の置き場所を書きます。

## 1. 二段階認証を2人とも付ける

[TWO-FACTOR-SETUP.md](TWO-FACTOR-SETUP.md) の手順どおりに、ケンタさんとマサトさんが「自分のアカウント」でそれぞれ設定します。1つのアカウントを2人で使い回しません。

- 対象：Google・GitHub・Cloudflare・LINE Developers・Stripe・Slack・ドメインの管理会社
- どこを押すか：各サービスの「設定・セキュリティ・二段階認証」の画面（詳しい押し方は手順書のサービスごとの節）
- 終わったらどうなるか：別の画面で入り直して入れること、予備の入り方が保管してあることを2人とも言える

## 2. 回復コードをしまって、取り出せるか確かめる

スマートフォンをなくしたときの予備の鍵です。封筒に入れて鍵のかかる場所へ置き、普段のPCやスマートフォンと一緒に持ち歩きません。回復コードやQRコードをGit・Slack・メール・この文書に貼りません。

- 終わったらどうなるか：スマートフォンなしでも保管場所から取り出せることを本人が確かめた

## 3. 権限の表を埋める

[TWO-FACTOR-SETUP.md](TWO-FACTOR-SETUP.md) の「誰に何の権限があるか」の表を、各サービスの管理画面と照らし合わせて埋めます。今はmusuboの中も含めて「未確認」です。名前と役割だけを書き、メールアドレスやIDは書きません。

- 終わったらどうなるか：不要な管理者が残っていないこと、どちらか1人の端末がなくても仕事を引き継げることが言える

## 4. musuboの二段階認証の鍵を確かめる（検証と本番）

管理画面の二段階認証の秘密を守る鍵 `TOTP_ENCRYPTION_KEY` が、検証と本番のWorkerに「あるかないか」だけ確かめます。無い所にだけオーナーが値を入れます。詳しくは [TWO-FACTOR-SETUP.md](TWO-FACTOR-SETUP.md) の鍵の節。

- どこを押すか：Cloudflare → Workers & Pages → 対象のWorker（検証 `nen-line-stg`・本番 `nen-line`）→ Settings → Variables and Secrets
- 終わったらどうなるか：検証・本番とも鍵が「ある」状態。すでにある鍵は上書きしない（登録済みの人が入れなくなるおそれがあるため）

## 5. 他の秘密がそろっているか名前だけ確かめる

値の中身は開きません。名前と「ある・ない」だけを見ます。検証と本番で同じ値を使い回さないことも見ます。

- 見る名前：`API_KEY`・`LINE_CREDENTIAL_ENCRYPTION_KEY`・`TURNSTILE_SECRET_KEY`・`GOOGLE_CALENDAR_CREDENTIAL_ENCRYPTION_KEY`
- どこを押すか：手順4と同じ Secrets の画面と、GitHubの Environment secrets の画面
- 終わったらどうなるか：必要な名前が検証・本番とも「ある」こと

## 6. リポジトリの公開範囲を決める

今のリポジトリ（`skmtmst/musubo`）は公開状態です。落ち着いたら非公開にするか（B-332）、公開のまま何に気を付けるかを決めます。非公開にしても過去のコピーや漏れた鍵は回収できません。

- どこを押すか：GitHub → リポジトリ → Settings → General → Danger Zone → Change repository visibility
- 終わったらどうなるか：`gh repo view skmtmst/musubo --json visibility` の結果と、決めた方針が記録してあること

## 7. 本番と検証が別物なのを確かめる

設定ファイルでは別になっていますが、同じ鍵や通知先を使っていないかを管理画面で照らし合わせます（[SECURITY-CHECKLIST.md](SECURITY-CHECKLIST.md) のS35）。

- 見る組み合わせ：Worker（検証 `nen-line-stg`・本番 `nen-line`）、管理画面（検証 `stg-admin.musubo.jp`・本番 `admin.musubo.jp`）、LINEチャネル（検証と本番）、決済（検証のsandboxと本番）
- 終わったらどうなるか：検証の操作が本番のお客さまに届かないと言えること
