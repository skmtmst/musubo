## 複数接続と契約枠（要件 §4-1）

- サービスごとに接続を複数積める。上限は各サービス 10個（`SNS_CONNECTION_LIMIT`）。
- 判定は画面ではなく `connection-slots.ts` が持つ。画面は返ってきた筋書き（`SnsAdditionPlan` / `SnsRemovalPlan`）を出すだけ。
- 契約枠は**両サービス共通の1つの数**（LINEアカウントごとに1つ）。`GET /api/settings/sns/connections` の契約枠を使い、記録が無い場合だけ既定 `SNS_DEFAULT_CONTRACTED` = 1個へ戻す。サービス別の2つの数は持たない。1枠 月額 `SNS_SLOT_UNIT_YEN`（¥3,300・税込）で Google・Instagram が**各1個ずつ同時に増える**（2枠なら各3個）。
- 有料の追加枠は画面で数え直さず `@line-crm/shared` の `linkedAccountSlots` を正本にする＝**max(0, max(Google数, Instagram数) − 1)**（要件 §3・§5 Q6'）。無料期間中は0円、追加した月は日割り。金額の文字は共通の料金表から作り、画面に数字を直書きしない。
- この数え方の帰結：少ないほうのサービスへの追加は有料枠が増えない（請求も増えない）。多いほうの個数が変わらない解除は減額しない。
- ［接続を追加する］を押したときの分かれ道（`planAddition`）：
  1. 接続数が既に10個 → `individual-quote`。F5 の個別見積もりの小窓で止める（認可へ進まない）。
  2. 追加後も契約枠の中 → `within-quota`。**料金の確認を挟まず**そのまま認可画面へ進む。
  3. 枠を超えるが請求の段が分からない → `billing-unknown`。下の「今の口で出せないもの」を見る。
  4. それ以外 → `over-quota`。F3（支払い中・日割りの請求あり）か F4（無料期間・0円）の小窓で料金を確認し、同意した場合にだけ認可画面へ進む。
- 解除（`planRemoval`）：F6 の確認の小窓。1件だけを解除し、ほかの接続のデータは消えない。有料枠の前後（`N枠 → M枠`）をいつも示し、減額の金額は有料枠が実際に減るときだけ出す（**契約枠は変わらない**）。
- 既存の単一接続の環境は、接続1件の一覧として同じ画面に出る（移行で画面側の作り替えは要らない）。

## Googleビジネス

- 口：`GET /api/restaurant-test/google/connection`（`restaurantGoogleApi.connection`）→ `googleSlots` で一覧の形に直す。
- 状態の札：接続済み／未接続／接続の異常（認可切れ・権限なし）。言葉と色は `status-labels.ts` の表だけを読む。
- 行の名前は店舗（ロケーション）名、控えめな1行は最終同期。
- 追加・つなぎ直し・解除はこのカード内だけで行う。追加は `connectStart` で Google の認可画面へ進み、戻り先は `/settings/sns?google=…`。店舗（ロケーション）の選択は Google 側まで含めて行い、**選ぶ段（`pending_location`）のときだけ**既存の選択の画面（`GoogleConnectionSettings`）をそのまま出す。
- 解除は版の確認つき（`expectedConnectionId` / `expectedConfirmationRevision`）。版が無い接続は版の確認なしで解除する。
- 読み取れないときは一覧の代わりに読み込み失敗の案内（`ListState kind="error"`・やり直せる）。

## Instagram

- 口：`GET /api/instagram/connection`（`api.instagram.connection`）→ `instagramSlots` で一覧の形に直す。
- 状態の札：接続済み／未接続／接続の異常／未設定。
- 行の名前は `@ユーザー名`、控えめな1行は接続した日。
- 追加・つなぎ直しは `POST /api/instagram/oauth/start` で受け取った URL へ飛ぶ。**ページを選ぶ段は出さない**（利用者の決め：Instagram にログインするだけでつながる）。
- 解除は確認の小窓 → `DELETE /api/instagram/connection`（`expectedVersion` に `connection.version`）。版が読めないときは解除せず、読み込み直しを案内する。
- 「できること」は2行（「DM を受信箱で読んで返せます」「Googleビジネスの投稿を Instagram にも同時に出せます」）。つないでいないときの見出しは「つなぐとできること」。
- 「設定がありません」（`unconfigured`／この環境に Meta の設定が無い）：注記だけを出し、押せないボタンは置かない。
- 戻り先：ログインから戻ると `/settings/sns?instagram=connected`（または `failed`）。帯でうまくいった／失敗を知らせ、閉じると `router.replace` で印を消す。同じ統括内の別LINEアカウントには同じInstagramを接続できる。**別の統括で使用中の場合は従来どおり拒否**し、統括の管理者への確認を案内する（`instagram_account_other_organization`）。接続の自動移動はしない。

## 閲覧しかできない人（F8・AGENTS.md §15）

- 操作を**消さない**。押せない状態にして、押せない理由を添える（`Button.lockedReason` / `RowMenu.lockedReason`）。理由は「オーナーか管理者だけが接続を変更できます」。
- 画面の先頭にも `ReadOnlyNotice` を1本出す。
- これは以前の「閲覧のみには接続・解除のボタンを置かない」という決めを**置き換える**（v7 F8 と AGENTS.md §15 が優先）。

## 契約枠・主連携・請求状態

- `GET /api/settings/sns/connections` から契約枠、請求状態、主連携、版を読む。別アカウントの返事や不正な枠数・請求日数は追加の許可に使わない。
- 契約記録のない既存アカウントは404になり、契約枠1・請求状態不明へ戻す。無料期間や契約を自動で作らない。
- GoogleとInstagramの全行は既存の接続一覧APIから読む。契約情報の取得に失敗しても、2件目以降の行と行ごとの操作対象を失わない。
- Googleの主連携はサーバーの指定を優先し、取得できない場合だけ既存の並びの先頭を使う。切替時は接続IDと版を送り、409では再読込して競合を知らせる。一覧と既定操作の並びは同じSQLの正本に従う。
- 契約枠内の追加は新規接続として認可へ進む。枠超過時は請求状態が分かる場合のみF3／F4で料金を確認し、同意後に新規接続へ進む。請求状態不明なら追加を許可しない。
- F6の次回請求日と減額の開始日はサーバーから取得できないため、日付を作って表示しない。
- 772・773の段階移行は完了した版を前提とする。DB適用・OAuth許可・検証用の契約設定は、コード配備とは別の承認と手順で扱う。
- ローカルでの料金確認には作り物の試験データを使う。実請求・実際の2件目接続の検証と混同しない。

### オーナーの決まりで解決したずれ（2026-11-17 独立検証の差し戻しへの回答）

正本の順位は `docs/v8-design-rules.md` §1「使いやすさ → オーナーの決まり → Pencil の ★V8 → 型・共通部品 → 動きの試験」。
次の5点は **オーナーの決まりが v7 の絵より上**なので、絵に戻さず決まりの値のままにする（再承認は求めない）。

- **カードの内側余白と中の行の間**：F1 `tIRy5`・F7 `ExtaM`・F8 `liCQN` の絵はカードの内側 36px・中の縦間隔 18px、F2 `VH2Ga` は 20px。実装は共通 `Card` の `padding="default"`（`--tpl-card-pad` → 16px）と `gap="normal"`（→ `--polish-space-field` 12px）のまま。§6.5-1「余白の段：8・12・16・24 の4段だけ。カードの内側 16、段（箱）の内側 24、欄と欄の間 12、ラベルと欄の間 8、カードの中の行の間 8」により 36・18・20 はどれも段に無い値。画面側で `--tpl-card-pad` を上書きすると共通 `Card` を使う全画面に及び、`AGENTS.md`「部品の見た目を画面側で上書きしない」にも反するため直さない。
- **カードの題の大きさ**：絵は 20px（F2 は 16px）、実装は 15px/700（`--tpl-e1-sns-title-size`）。§6.5-2「段の題 15/700」。カードの題は段の題にあたる。
- **枠説明・主連携説明の見た目**：絵は 14px・#6F6F6B、実装は `--text-caption`（12px）・`--color-ink-secondary`。§6.5-2「補足 12（`--color-ink-secondary`）、注 12（`--color-ink-faint`）」。14px と生の色値は段にも変数にも無い。
- **細い画面（390px）の左右余白・カード幅・ページの題**：絵は左右 16px・カード幅 358px・題 20px。実装は設定の共通外枠のまま（左右 40px・カード幅 310px）で、題は `PageHeading` の 32/600。§6.48「設定は PC と iPad だけ。…**管理画面を 390px に縮めない**」「崩れの見張りは /m の住所だけを 390・430 で見る（全機能の管理画面は 390 で点検しない決まり＝§2 はそのまま）」。絵の 16/358/20 は `--phone-*`（`mobile-frame.module.css`）の値で、§6.48「外枠の中だけで効く。PC の値は変えない」により `/m` の中だけの値。ページの題は §6.5-2「ページの題 32/600」。

- **窓の本文と操作の段の間（2026-11-17 ローカル実画面の実測で判明）**：v8 の Dialog（F3 `I8GjHC`・F4 `mO9BO`・F5 `rGNts`・F6 `lfR6k`：いずれも `w=560, padding=24, gap=16`）は本文と操作の段の間も 16px。実画面は 24px になる。共通の窓の部品が `dialog.module.css`（`html:root .panel:not([data-layout]):not([data-design-layout]) > .footer > .actions` に `padding-block-start: var(--polish-window-divider-space)`＝24px）で**線から操作までの上だけを全画面でそろえており**、画面側が渡す上の値（`--tpl-e1-sns-slot-dlg-foot-pad` の 16px）には効かない。この決めは SNS だけでなく `reorder-dialog.tsx`（10px）・`mark-list.tsx`（14px）・`registration-style-dialog.tsx`・`wizard.tsx`・`preparing-dialog.tsx`（16px）など窓を出す全画面に同じようにかかっており、前からの共通の形。24px は §6.5-1 の余白の段（8・12・16・24）の中の値。共通の決めを SNS のために外すと窓を使う全画面と V8 の見張り（住所×画面幅 276通り）に及び、`AGENTS.md`「部品の見た目を画面側で上書きしない」にも反するため**共通側は直さない**。左右 24・下 24 はこのまま画面側の値を使う。
