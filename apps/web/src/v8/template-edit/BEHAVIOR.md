# テンプレートの作る・編集の動き（BEHAVIOR.md）

対象：`message.tsx`（メッセージを作る・編集：u5YC6／1152 は a1k3d／競合は NCbYn）と
`asset.tsx`（クーポンを作る S6FEuB・リサーチを作る EsYo4）と `rich.tsx`（リッチメッセージを作る EFV8l）。
入口・公開名・API・試験の案内は [README](README.md)。

## 入口と受け付ける URL・指定（今と同じ名前・同じ意味）
- `app/templates/edit/page.tsx`：`edit.tsx` を直接表示し、kindで編集対象を選ぶ。管理画面はV8に固定。
- `?kind=rich_message`：リッチメッセージを作る（`rich.tsx`）。
- `?id=<テンプレートID>`：編集。無ければ作る。
- `?kind=coupon` ／ `?kind=research`：資産の作る画面（`asset.tsx`）。
- `?visual=1`：見本の中身を入れて開く（撮影・見本用。今と同じ値）。
- `?example=<見本の番号>`（F-5・2026-10-07 に足した）：作るときだけ、`GET /api/templates/examples` の見本の名前と本文（テキスト）を1回入れて開く。保存はしない（入力と同じ扱いなので、名前があれば自動保存の決まりどおりに下書きができる）。見本が無い・読めないときは白紙のまま「見本が見つかりませんでした／読み込めませんでした。白紙から作れます。」

## 権限
- 役割はサーバー（`/api/staff/me`・`useStaffRole`）から読む。共通の機能権限 `useFeatureAccess('templates')` で変更可否を決める。確認中・取得失敗・閲覧のみでは変更操作を隠す。統括からはhostのreadOnlyを優先する。最後の守りはサーバーの 403。

## メッセージ（message.tsx）
- 読み込み：`GET /api/templates/:id`。形の番人（`isTemplateDetailData`）に合わない応答は「読み込めませんでした。開き直してください。」で保存を閉じる。
  URL の id が変わった瞬間に前の中身を捨てる（描画中に作り直す）。遅れて届いた古い応答は世代で捨てる。
- フォルダ：`api.folders.list('template', <所属アカウント>)`。保存値は `folderId`（未分類＝null）。
- 差し込み候補：友だち情報・共通情報（機能オフの 403 は「候補なし」）。既存テンプレートは**所属アカウントに固定**。
  上のバーで別アカウントへ替えると保存を閉じ、食い違いの知らせを出す（`ACCOUNT_MISMATCH_MESSAGE`）。
- 本文の下の「差し込む」：名前は押すとすぐ、友だち情報・共通情報・配信日・その他は一覧から選ぶ。
  その他の「目標日までの日数…」は窓で日付を選ぶ（`{{days_until:YYYY-MM-DD}}`）。カーソルの位置へ入れる。
  機能がオフの友だち情報・共通情報は出さない。候補が無い・読み込み中は押せず、理由を title に出す。
- 数：`n / 5,000`。4,500 を超えると「複数のメッセージに分かれて届きます」。
- 新しく作るメッセージはテキストだけ（2026-10-08夜）。形の切り替えは出さない。既存のカード型・画像は保存済みの形のまま編集でき、新規作成できない案内の帯を出す。カード型は JSON の形を入力中に見て、壊れていれば理由を出し保存を断る。
- 本文の中の URL：本文から拾って行に並べる。短縮して数えるのは常にオン（切れないので鍵つきのスイッチ）。
  URL の行にも「短縮して数える（いつもオン・変更できません）」と出し、押せない理由を見える形で伝える。オンの状態、保存する本文と URL は変えない。
  リンク名（計測に出る名前）を書く欄は**口が無い**（配信のときに自動で付く）。絵にある入力欄は置いていない。
- 右の列：送るときの名前／（使われている場所があれば）変更が使われる場所／届き方（本物のスマホ・見本 141さんで差し込み後）。
  1152 ではスマホを隠し「LINEでの見え方を見る」で窓に出す。
- 下書きを保存：`PUT /api/templates/:id`（新規は `POST /api/templates`）→ 一覧へ。断る条件（名前・本文・カード型の形・所属の食い違い・読み込み中）に当たったら API を呼ばない。
- 保存して公開：保存 → 詳細を読み直す → 使われている場所があれば確認の窓（cuR8I）→ `POST /api/templates/:id/publish`（表示中の版・下書きの版を添える）→ 一覧へ。
- **409（ほかの人が先に保存・公開した）**：保存でも公開でも、最新を1回読み、頭の下に競合の帯（NCbYn）
  「ほかの人が HH:MM にテンプレート「名前」を保存しました」を出す。入力は捨てない。
  出口は「違いを比べる」（最新と自分の下書きの違いを窓で見せる。画面は書き換えない）と「最新を読み込んで続ける」。
  帯が出ている間、主ボタンは「比べてから保存」（比べる窓を開く）。下書きを保存を押し直すと、もう一度保存を試す。
  ※今の画面との違い：今は保存の 409 を文だけで出していた。公開の 409 は今も帯。
- 離れるときの確認：保存していない変更があれば、離れる前に確認の窓（useUnsavedGuard）。

## クーポン・リサーチ（asset.tsx）
- 保存：`POST /api/broadcast-message-assets`（`kind`・`name`・`payload`・`payload.folder` はフォルダ名）。今と同じ形。
  資産の口に「公開」は無いので、下書きを保存は保存してこの画面に留まり、保存して公開は保存して一覧へ戻る（今と同じ）。
  1回保存したら、もう一度は保存できない（一覧へ戻る）。
- クーポン：期間（開始・終了は必須、終了は開始より後）・1人が使える回数・受け取れる人・抽選（オンで当たる確率 1〜100・当選人数の上限）・使われたときに行うこと。
  画像は「中身」の枠を押して窓で選ぶ（登録メディアから選ぶ・URL を書く・外す）。
  **クーポン名**は絵の欄。保存値は `payload.title`（任意）。配信の本文は今までどおり「使うときの説明」。
- リサーチ：受付の開始・終了・はじめのあいさつ・質問（10問まで・選択肢は13まで・必ず答えてもらう・答え方・並べ替えは問の左の印から「上へ／下へ」・削除する）。必ず答えてもらうはスイッチ。選択肢は札の並びで、札を押すと「選択肢「〜」が選ばれたら」の下に、その選択肢の行うこと（タグを付ける・スコアを足す。保存の形は今までどおり）を共通の「行うこと」の行で出す（EsYo4・2026-10-15）・答え終わったときに行うこと・答えてもらう人（タグ、任意）。
  答えてもらう人は絵に無いので、いちばん下の箱に置いた（今ある機能を落とさないため）。
- 右の列：クーポンは「公開したあとに見られる数」（保存前は —、抽選しないときは「抽選なし」）、リサーチは「回答フォームとの使い分け」。届き方は、クーポンはスマホの中のカード、リサーチはお客さまが答える画面（回答フォームの LIFF と同じ形・次へは下に固定。B-173）。

## リッチメッセージ（rich.tsx）
- 形・面の座標・保存値は現役の `rich.tsx` と関連する純粋な関数で組み立てる。
- 保存：`POST /api/broadcast-message-assets`（`kind: rich_message`・`payload` は imageUrl・imageMediaId・imageMediaKind・shape・tapAreas・folder）。今と同じ形。
  公開の口が無いので、下書きを保存は保存して留まり、保存して公開は保存して一覧へ戻る（クーポン・リサーチと同じ）。
- 面の分け方：1面・上下2面・左右2面・上1・下2・4面・6面。設定のある面が消える形へ替えるときは確かめの窓を出す。
- 画像：160角の枠か「登録メディアから選ぶ」で選ぶ。URL を直接書く欄も残した（絵には無い。今の画面にある機能）。
- 押した面ごとの動き（2026-10-09・採用案 Wmch0）：共通部品 TapAreaEditor。画像（幅 320）の上の面か右の一覧（記号・場所の名前・動きの要約／未設定）を押して選び、下にその面の1行（面の札「A 上」・押したら・中身）。
  押したら＋中身は共通の欄 `components/shared/tap-action-field`（2026-10-09 B-129・YPzmo）：未設定＋6つ（URL・テキスト・予約・回答フォーム・予約履歴・来店スタンプ）。テキストは `actionType: 'message'`（400文字まで）、LIFF の4つはアカウントの LIFF の URL（`actionType: 'uri'`）で送る。前の「動きを実行する」（postback）は保存で断られる（イメージマップは postback を持てない）ので外した。統括は URL・テキストだけ。未設定の面があれば下に注意を出す。
- 右の列：リッチメニューとの違い・届き方（正方形の画像に面の線を重ねた見本）。
- `?visual=1`：見本の中身（夏のキャンペーン告知・上下2面・上は URL・下は動き）。

## 統括の入口から使う（`host`・2026-10-08）
- `host.ts` の口を渡すと、統括のテンプレート（`src/v8/hq-templates/console.tsx`）から同じ画面を使う。保存は呼ぶ側（統括の口）、主ボタンは［保存して配る］、戻る先は `/hq/templates`。
- 渡したときは、店の口（読み込み・自動保存・公開・店のフォルダ・差し込み候補）を呼ばない。店のアカウントに結びつく欄（登録メディア・行うこと・答えてもらう人）は出さない。
- 渡さないときの動き（店の画面）は今までと同じ。
- リッチメッセージ（2026-10-08）：統括では画像をパソコンから選び、統括の口で LINE の5サイズを作る（`host.uploadRichImage`）。面の動きは「URLを開く」だけ。
- 編集（2026-10-08）：`host.initialContent` を渡すと、保存してある中身（クーポン・リサーチの payload・リッチメッセージの画像と面）から始める。

## リッチビデオ（G-2・2026-10-08 オーナー採用）
- `?kind=rich_video`（作る）、`?kind=rich_video&id=<ID>`（編集）。一覧と詳細の編集入口もこの種類へ渡す。
- 保存値は既存の `templates.message_type=imagemap` と JSON の `video`。表・列・migrationは追加しない。
- MP4は既存の直接アップロード（200MBまで）。動画から同じ縦横比のJPEGを作る。作れなければ同じ縦横比のJPEG・PNG（1MBまで）を選ぶ。
- 保存口で動画の所属アカウント・実際の容量・MIME・安全性検査とHTTPS URLを確認し、プレビューを既存の仕組みで240・300・460・700・1040幅へ変換する。
- ボタンを出すときは文字とHTTPSリンク（1,000文字まで）、出さないときは `externalLink` 自体を保存・送信しない。通知文は1〜1,500文字。
- ［保存する］で下書き保存→一覧。配信で使う前に、既存の詳細画面で公開する（更新も公開版は変えない）。公開後は一斉配信・シナリオ・自動応答で同じ動画付きImagemapを送る。
- 入力不足は該当欄の赤枠・理由・focus。上の帯は通信や保存の失敗だけ。閲覧のみには保存・ファイル選択・フォルダ選択・ボタン選択・スイッチを置かない。
- 読み込み失敗・所属アカウント不一致は保存不可。アカウントを替えた後に届いた古いアップロード結果は捨てる。
- 統括の配布口は画像1枚8MB・配布全体16MBで、200MB動画を扱えない。今回は店舗側のみ。統括へ未完成の種類は出さない。
